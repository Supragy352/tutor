The PID course · 8 stages · C

Build your own PID controller

Your program reads a config line like kp=2.5 ki=1 dt=0.1 from stdin, then one <setpoint> <measurement> per line, and prints the control output to 4 decimal places. Each stage adds one idea to the same controller.

  1. Proportional controlParse the config and push in proportion to the error.
  2. Integral term and the fixed timestepKeep state between steps and accumulate error × dt.
  3. Derivative termReact to how fast the error is changing.
  4. Output clampingRespect the actuator's min and max.
  5. Integral anti-windupStop the integral growing while the output is saturated.
  6. No derivative kickTake the derivative of the measurement so setpoint jumps don't spike the output.
  7. Closing the loop--sim: drive a first-order plant and print its trajectory.
  8. Tuning--tune: score candidate gains by IAE and pick the best.
Run the course

From zero to stage 1

You need Rust (cargo), gcc, git and a logged-in Claude Code. The local reviewer is optional. If Ollama isn't reachable, tutor skips the review and carries on.

  1. Get tutor

    git clone https://github.com/Supragy352/tutor && cargo install --path tutor

    This puts tutor on your PATH. Keep the clone: the courses live in its challenges/ folder.

  2. Start a workspace

    git init pid && cd pid
tutor init ../tutor/challenges/pid --build "gcc -O2 -Wall -o pid main.c -lm" ./pid

    This installs the commit hook and keeps your progress in tutor.toml. On Windows, name the binary pid.exe.

  3. Open the dashboard

    tutor serve

    Then visit http://localhost:4242 for the stage instructions, your progress, test results, reviewer notes and hints. It updates when you commit from a terminal. tutor show prints the current stage if you'd rather stay in the terminal.

  4. Write code, commit

    git commit -am "stage 1: proportional"

    The hook compiles main.c, runs every test up to your stage, and asks the reviewer. Pass and you unlock the next stage. Fail and you see the stdin, expected and actual output for each failing case.

  5. Stuck? Ask

    tutor hint

    Claude Code reads your folder and explains the concept you're missing. It also steps in on its own after 3 failed runs on the same stage.

Commands

CommandWhat it does
tutor init <course> [--build "cmd"] <run>Start a course in the current folder and install the git hook.
tutor testBuild, run the tests and the review. Advances on pass.
tutor serve [port]Web dashboard on localhost (default port 4242).
tutor showPrint the current stage's instructions.
tutor hintAsk Claude Code for help on the current stage.
tutor new <slug> "<goal>"Have Claude Code design a new course into challenges/<slug>.
tutor verify <course>Check a course's tests against its hidden reference solution.
TUTOR_LLM, TUTOR_MODELOllama address (default http://localhost:11434, or off) and model (default qwen3.6:35b).
Learn anything

Make your own course

Describe what you want to build. Claude Code breaks it into 5–8 stages, writes the tests, and writes a hidden reference solution. tutor only accepts the course once that solution passes every test, so you never end up chasing a broken test. If it fails, the failures go back to Claude Code, up to three attempts.

tutor new lisp "Build a Lisp interpreter with a REPL: tokenizer, parser, eval, lambdas and closures"
tutor runs entirely on your machine and your tailnet. Courses are plain TOML in challenges/.
